# Dental Atlas Constitution

## Core Principles

### I. Verified Clinical Content
Only clinic-published or project-verified names, prices, addresses, contacts, specialties, and booking links may be shown. Unknown details are labelled unavailable rather than inferred.

### II. Safe Booking Handoff
The experience may preserve a user's branch and service context, but it must hand off to an official booking channel and must never invent doctors, slots, confirmation, or successful appointments.

### III. Accessible Mobile-First UX
Every primary task must work at 320–390 px as well as desktop widths. Focus states, keyboard navigation, reduced motion, touch targets, readable contrast, and safe-area spacing are mandatory.

### IV. SEO Without Duplication
Indexable pages must have unique, accurate metadata and canonical URLs. Content must be useful and specific, without mass-generated filler or duplicate branch claims.

### V. Reviewable Releases
The existing preview remains intact. Improvements ship on a separate branch with reproducible checks and no production deployment or merge unless explicitly requested.

## Governance

These principles are mandatory for the Dental Atlas 4.0 branch. A change that conflicts with verified content, booking safety, accessibility, or release isolation must be corrected before review. The current preview and its data remain available for comparison.
